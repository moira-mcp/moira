---
title: Workflow Management Flow
description: Долговечный evidence-aware workflow authoring с optional static progress design и independent design/artifact review.
---

Workflow Management Flow создаёт новый Moira workflow или редактирует одну полную существующую definition через source preparation, requirements, design, official tooling, independent review и явно разрешённую publication.

```bash
mcp__moira__start({
  action: "prepare",
  workflowId: "moira/workflow-management-flow",
  parentExecutionId: "none"
})
mcp__moira__start({ action: "execute", startAttemptId: "<ID попытки запуска из prepare>" })
```

## Authoring lifecycle

Flow определяет create/edit identity, online/offline source boundaries, local source hint и autonomous/interactive mode. Он материализует execution-correlated workspace с текущим authoring reference, получает полные server/repository candidates, записывает provenance и semantic differences и никогда механически не объединяет JSON.

Requirements и опциональный full antipattern audit формируют один outcome-oriented design contract. Independent pre-mutation review должен пройти до изменений полного артефакта через official workflow CLI. Результат проходит validation и официальный structural schema projection, затем independently review по полному JSON, requirements, design, authority и evidence modalities.

Design contract выражает каждое решение на той ноде, у которой есть данные для него — routing `cases` и свёрнутые `expressions` на решающей ноде, `success`, когда ни один кейс не сработал, — и оставляет отдельную ноду condition или expression только для общего или самостоятельного решения; ревью считают находкой ноду маршрутизации, которая лишь маршрутизирует или считает то, что предыдущая нода уже знает (avoidable routing scaffolding). Когда этап идёт по списку, который flow хранит в переменных, дизайн привязывает блок прогресса к нему, чтобы запуск показывал done/total и текущий элемент.

Если у workflow есть содержательные пользовательские этапы, этот же lifecycle проектирует его представление процесса: короткую цепочку блоков в порядке процесса, каждый с описанием в одно предложение, где каждая нода графа, включая ноды маршрутизации, принадлежит одному блоку, каждая связь, выходящая из блока, подписана решением, которое она выражает, каждый возврат объясняет причину и выход, а хабы стоят после блоков, которые в них ведут. Ворота дизайна WMF задают это как часть контракта до мутации, ворота сборки создают это официальным CLI и завершаются только когда `derive` не показывает диагностик, а ревью проверяют, что подписи, объяснения циклов, описания и порядок соответствуют графу. Условия и маршруты исполнения остаются в основном графе workflow; запуск показывается по записанному маршруту. Единые projection и visual model используются и интерфейсом, и серверным PNG renderer. Агент может запросить короткоживущую одноразовую ссылку на PNG, а авторизованный Telegram node прикладывает изображение напрямую, не сохраняя этот token в состоянии workflow. WMF не добавляет progress, если он будет декоративным.

Когда один блок представляет несколько текущих ролей, WMF может спроектировать
`progressActiveLabel` на его waiting nodes. Он показывается только для точной текущей primary
node; неактивные блоки сохраняют стабильный base label. WMF требует, чтобы каждая переменная
была авторитетна на всех достигающих node маршрутах, и отклоняет stale counters, неверный scope и
progress-owned state или routing.

Artifact-owned findings исправляют workflow и повторяют stale gates. Invalid criteria или upstream process defects приводят к replan. Final report описывает точные starts, teleports, terminals, routes, cycles, reachability, coverage, data flow и каждый frozen semantic guarantee.

## Publication и local synchronization

Server upload — отдельное решение: standard, copy-new или явно разрешённый admin override. Autonomous mode не придумывает upload authority. Repository synchronization сохраняет identity выбранного target и не пишет посторонние paths. WMF создаёт definition, но не выполняет downstream task будущего workflow.
