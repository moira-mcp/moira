---
title: Todo List
description: Минимальный автономный checklist с одной задачей и кратким локальным evidence
---

Todo List превращает одну цель в упорядоченный checklist и выдаёт по одной задаче. Это намеренно не журнал результатов: workflow не классифицирует исходы задач, не агрегирует evidence и не строит итоговый отчёт.

## Запуск workflow

```js
mcp__moira__start({ workflowId: "moira/todo-list", parentExecutionId: "none" })
```

Первый шаг получает от 1 до 100 задач. Если в текущем контексте пользователя или вызывающей стороны
уже есть корректный по схеме готовый список, агент передаёт его без изменений. Иначе тот же шаг
один раз составляет список из текущей цели. Каждая задача содержит только:

- `action`: самодостаточную работу, которую нужно выполнить;
- `expected_result`: наблюдаемое условие завершения.

Обе строки непустые и ограничены 1 000 символами. Позиция в массиве служит идентификатором задачи; агент не передаёт ID, курсор, общее число, статусы или коды результата.

## Выполнение

Todo List владеет курсором с единицы. Он проецирует текущую задачу, сообщает агенту действие и ожидаемый результат и ждёт. Агент выполняет реальную работу и проверяет результат до вызова `step()` ровно с одним полем:

```json
{ "evidence": "Целевая команда тестов прошла." }
```

`evidence` — непустая строка длиной не больше 500 символов. Это краткое подтверждение текущего шага; оно остаётся локальным для ноды и не копируется в глобальный массив или терминальный отчёт.

Если задача не завершена или заблокирована, агент не вызывает `step()`. Он сообщает пользователю проверенную причину, поэтому курсор остаётся на текущей задаче. Корректное по JSON Schema подтверждение продвигает курсор ровно один раз. Исчерпание упорядоченного массива завершает workflow.

## Передача готового checklist

Вызывающая сторона запускает Todo как дочерний workflow и включает готовый корректный по схеме
массив задач в контекст дочерней задачи. Первый шаг Todo передаёт этот массив обычным ответом
`step()`:

```json
{
  "tasks": [
    {
      "action": "Проверить реализованное требование",
      "expected_result": "Предметный отчёт вызывающей стороны содержит проверенный результат"
    }
  ]
}
```

Отдельной ветки supplied tasks и pre-start input mapping нет. Intake-шаг сохраняет готовый массив,
а не перепланирует его, затем начинает с первого пункта. Предметные результаты остаются у
вызывающей стороны. Например, workflow проверки требований должен сам записывать отчёт и владеть
классификациями `COVERED`/`GAP`, а не использовать Todo List для их передачи.

## Контракт завершения

Todo List завершается с пустым терминальным результатом: `{}`. Завершение означает, что каждый пункт checklist получил корректное по схеме подтверждение после выполнения и проверки агентом. Evidence отдельных пунктов остаётся в истории взаимодействия исполнения; накопленный output API для него не обещается.

Если вызывающему subgraph нужны предметные данные, он должен сформировать и сохранить их сам. Ветка Todo `success` означает только достижение End-ноды checklist.
