---

Moira User Onboarding объясняет directives, completion conditions, input schemas и verified progression, помогая новому пользователю выбрать workflow из полного текущего разрешённого public catalog.

```bash
mcp__moira__execution({
  action: "prepare",
  workflowId: "moira/user-onboarding",
  parentExecutionId: "none"
})
mcp__moira__execution({ action: "execute", startAttemptId: "<ID попытки запуска из prepare>" })
```

Onboarding вызывает `workflow({ action: "list" })` постранично, пока не увидит каждый workflow из reported total. Он воспринимает names/descriptions как данные, показывает каждую identity ровно один раз и объясняет purpose, deliverable, cost/durability profile, authority boundary и ближайшие альтернативы. Frozen catalog не используется.

Пользователь выбирает точный qualified `owner/slug` или create/edit path через `moira/workflow-management-flow`, затем явно выбирает start или defer. Start подготавливает ровно этот workflow как child onboarding, передаёт выданный Start attempt ID в execute без изменений и принимает только подтверждённое создание выполнения и его реальный Process ID из успешного execute. Зарезервированный Process ID из prepare ещё не является child execution. Он использует `skipNotificationCheck: true` только для пропуска preflight опциональных обычных уведомлений; флаг не разрешает notification, не меняет authority child process и не обходит доверенную доставку PIN для lock nodes.

Если выбранный workflow содержит lock node, execute требует корректные Telegram bot token и chat ID текущего пользователя до создания child execution. Его стабильный отказ `START_PRECONDITION_CHANGED` с инструкцией настройки не содержит Process ID и оставляет handoff незавершённым. Onboarding не настраивает settings и не запускает другой workflow; точный выбранный workflow подготавливается заново только после изменения соответствующего внешнего состояния. При потере ответа вместо этого сохраняется исходная попытка запуска для получения её исхода. Явный `ATTEMPT_OUTCOME_UNKNOWN` требует проверки через `execution` с `action: "current_step"` или `action: "execution_context"`, а не автоматического execute или новой подготовки. Defer не выполняет внешнюю мутацию.

Onboarding не создаёт durable artifacts, не настраивает settings, не публикует, не deploy, не меняет production и не выполняет substantive work child workflow. Если цель уже известна, запускайте подходящий workflow напрямую.

## Прогресс выполнения

Карточка запуска показывает три блока: Welcome (поприветствовать пользователя и понять, что он хочет сделать) → Choose (указать подходящий workflow или предложить создать новый) → Launch (запустить выбранный workflow сейчас или завершить). Неясный ответ возвращает к Welcome, пока пользователь не сделает корректный выбор. Блоки выводятся из исполняемого графа и не добавляют маршрутов.
