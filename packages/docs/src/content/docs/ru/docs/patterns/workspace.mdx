## Назначение

Создание выделенной директории рабочего пространства для выполнения workflow. Все рабочие файлы (планы, результаты, отчёты, резервные копии) хранятся в одном месте, сохраняя чистоту проекта.

## Структура

```
./moira-ws/{workspace-name}/
├── process-id.txt       # ID выполнения workflow для восстановления
├── development-plan.md  # Планы и спецификации
├── step-1/              # Результаты конкретных шагов
│   └── step-results.md
├── *.backup.json        # Файлы резервных копий
└── ...                  # Прочие рабочие файлы
```

## Расположение рабочего пространства

Все рабочие пространства создаются в поддиректории `./moira-ws/` **текущего проекта**:

```
./moira-ws/{workspace-name}/
```

<Aside type="caution">
  НЕ создавайте рабочие пространства в корне проекта (`./feature-name/`) или в других местах. Всегда
  используйте `./moira-ws/` для единообразия.
</Aside>

## Соглашение об именовании

Формат: `{short-name}-{YYYYMMDD}-{HHMM}`

- `short-name`: Краткое описание задачи (макс. 20 символов, kebab-case)
- Дата и время создания

Примеры:

- `wmf-edit-20251211-2145`
- `auth-fix-20251212-0930`
- `api-refactor-20251215-1400`

## Реализация

### Владелец рабочего пространства

Рабочее пространство создаёт первая ответственность, у которой есть настоящая работа: директорию,
`process-id.txt`, связывающий её с запуском, и долговечные источники, которыми она владеет, — всё в
одном ходе. Нода, единственная задача которой создать директорию, добавляет ход, но не добавляет
суждения.

```json
{
  "type": "agent-directive",
  "id": "get-task",
  "directive": "Establish the complete task contract from the triggering conversation. Create ./moira-ws/{task-short-name}-{YYYYMMDD}-{HHMM}/ and its required subdirectories, write {{executionId}} to process-id.txt, write the complete task contract once to task.md, and initialize execution.md for the evidence entries that follow. Return the exact workspace and task file paths.",
  "completionCondition": "The workspace, process correlation, and complete task contract exist at the returned paths",
  "inputSchema": {
    "type": "object",
    "properties": {
      "workspace_path": {
        "type": "string",
        "pattern": "^\\./moira-ws/[a-z0-9-]+-\\d{8}-\\d{4}/$",
        "description": "Path to the created workspace"
      },
      "task_file": {
        "type": "string",
        "description": "Complete task contract written in the same turn"
      }
    },
    "required": ["workspace_path", "task_file"]
  },
  "connections": { "success": "create-plan" }
}
```

Возвращённый путь сам по себе ничего не доказывает: существования и полноты файлов требует completion
condition, а `pattern` в схеме ограничивает лишь форму строки.

### Использование пути рабочего пространства

Ссылайтесь на `{{workspace_path}}` в последующих директивах:

```json
{
  "directive": "Save development plan to {{workspace_path}}development-plan.md"
}
```

```json
{
  "directive": "Create step results in {{workspace_path}}step-{{current_step}}/step-results.md"
}
```

## Что хранить в рабочем пространстве

**Включайте:**

- `process-id.txt` — ID выполнения для восстановления workflow
- Планы и спецификации (файлы `.md`)
- Результаты и отчёты по шагам
- Резервные копии перед редактированием
- Временные результаты анализа

**Исключайте:**

- Исходный код проекта
- `node_modules` или зависимости
- Большие бинарные файлы
- Секреты и учётные данные

## Настройка Git

Добавьте `./moira-ws/` в `.gitignore`:

```gitignore
# Рабочие пространства Moira workflow
moira-ws/
```

Рабочие пространства — это временные рабочие директории, которые не следует коммитить.

## Восстановление

При прерывании workflow агент может:

1. Прочитать `process-id.txt` из рабочего пространства
2. Возобновить выполнение по сохранённому ID процесса
3. Продолжить с последнего завершённого шага

```json
{
  "directive": "Check for existing workspace in ./moira-ws/\nIf found, read process-id.txt and resume workflow"
}
```

## Реальный пример

`moira/quick-task` отдаёт рабочее пространство своему первому шагу: он в том же ходе пишет контракт
задачи и журнал доказательств и возвращает оба пути:

```text
./moira-ws/quick-task-<executionId>/
├── process-id.txt
├── task.md
├── execution.md
├── plans/<iteration>/{plan.md, review.md, decision.md, change.md}
└── result-reviews/<iteration>/{review.md, decision.md, change.md}
```

Числовые директории итераций публикуются только когда запись полна, поэтому возобновлённый запуск
отличает завершённую итерацию от брошенной.
