Обычные уведомления workflow Moira отправляет через `user-notification`, а сама Moira сообщает, когда
запуск начинает ждать вас (шаг с пометкой `humanGate` или вопрос агента), а для помеченного шага с
`remindAfter` один раз напоминает — и тогда, когда первое сообщение об этом шаге workflow отправил сам
(`notify: "off"`); если
Telegram включён, встроенный адаптер в обоих случаях использует bot и chat ID текущего пользователя. Устаревшая
`telegram-notification` сохраняет Telegram-only совместимость, а `lock` использует отдельный
доверенный Telegram-путь для доставки PIN.

## Настройка

### 1. Создание бота через @BotFather

1. Откройте Telegram и найдите `@BotFather`
2. Отправьте `/newbot`
3. Выберите отображаемое имя (например, "My Moira Notifications")
4. Выберите username, оканчивающийся на `bot` (например, `my_moira_bot`)
5. BotFather ответит токеном бота — скопируйте его (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`)

### 2. Получение Chat ID

**Способ A — @userinfobot:**

1. Найдите `@userinfobot` в Telegram
2. Отправьте любое сообщение
3. Бот ответит вашим user ID — это и есть ваш chat ID

Не помещайте токен бота в URL браузера. URL может остаться в истории, скриншотах, proxy и логах. Используйте `@userinfobot` или guided workflow.

### 3. Сохранение настроек

1. Откройте Moira и перейдите в **Настройки → Уведомления**
2. Найдите карточку **Telegram**; кнопка **Настройка Telegram** в заголовке раздела проводит по этим шагам
3. Введите **Токен бота** в соответствующее поле
4. Введите **ID чата** в соответствующее поле
5. Убедитесь, что **Присылать уведомления в Telegram** включено
6. Нажмите **Сохранить** для каждой настройки

### 4. Отправка тестового уведомления

Когда карточка Telegram показывает состояние **Готов**, нажмите **Отправить тест**. Moira использует
сохранённые настройки для фиксированного тестового сообщения; браузер не отправляет bot token или
chat ID повторно. Вы должны получить сообщение от бота в Telegram.

:::caution[Важно]
Перед тестированием необходимо отправить хотя бы одно сообщение боту в Telegram. Telegram API требует этого прежде чем бот сможет отправлять вам сообщения.
:::

## Уведомления администраторам о регистрации

Каждый администратор-получатель сначала настраивает свою карточку Telegram, как описано выше.
Аккаунт должен быть допущен политикой доступа установки: заблокированный или ожидающий одобрения
администратор, а также выключенный или неполностью настроенный канал Telegram не получает сообщение
о регистрации.

В **Админка → Менеджер настроек → Значения → Системные настройки** используйте **Уведомлять
администраторов о новых регистрациях** и сохраните. Глобальная boolean-настройка
`system.notify_admins_on_registration` включена по умолчанию. Выключение прекращает сообщения о
регистрации для всей установки, не меняя личные настройки Telegram. Переключатель не хранит ещё
один токен бота или ID чата.

Успешное создание аккаунта через email или OAuth вызывает обычное текстовое сообщение с именем,
email, временем регистрации и ссылкой на карточку аккаунта в админке. Вход существующего
пользователя, привязка другого провайдера и неуспешная регистрация не вызывают такое сообщение.
Кнопка **Отправить тест** проверяет доставку по сохранённым настройкам Telegram; она не имитирует
регистрацию.

Доставка не задерживает ответ регистрации. Отказ одного получателя не мешает остальным
администраторам и не отменяет созданный аккаунт. Доставка выполняется по возможности: таймаут,
потеря ответа или прерывание процесса могут оставить исход неизвестным, и Moira не пересылает
событие автоматически.

## Настройка через агента

При использовании Moira через MCP-клиент (Claude Code, Claude Desktop) можно запустить пошаговый workflow настройки:

```
start({
  action: "prepare",
  workflowId: "moira/telegram-setup",
  parentExecutionId: "none",
  skipNotificationCheck: true
})
start({ action: "execute", startAttemptId: "<ID попытки запуска из prepare>" })
```

Укажите `skipNotificationCheck: true` при подготовке этого bootstrap workflow, когда Telegram ещё не настроен; иначе execute вернёт стабильный ответ `START_PRECONDITION_CHANGED` из-за его legacy test node `telegram-notification`. Флаг обходит только preflight опциональных обычных уведомлений. `skipTelegramCheck` остаётся устаревшим alias с тем же поведением. Ни один флаг не обходит доверенную доставку PIN для ноды `lock`.

Workflow проверяет masked существующие настройки, позволяет протестировать или явно заменить их, не возвращает credentials, проверяет сохранённое состояние, отправляет secret-free тест и подтверждает фактическое получение.

## Блокировки workflow

Workflow с нодой `lock` запускается только при корректных bot token и chat ID текущего пользователя. Execute проверяет эту конфигурацию до создания execution и при её отсутствии сохраняет ответ `START_PRECONDITION_CHANGED`. Когда выполнение достигает ноды, Moira отправляет сгенерированный PIN только в этот настроенный chat и активирует блокировку после успешной отправки. Если последующая отправка завершается ошибкой, эта попытка не оставляет доступной блокировки; повторите ту же ноду после восстановления доставки.

MCP-ответы и ответы workflow не раскрывают сгенерированный PIN. Для разблокировки введите PIN, отдельно переданный пользователем, или нажмите Approve в Telegram.

## Решение проблем

### Ошибка "Chat not found"

Бот не может отправлять сообщения пока вы не напишете ему первым. Откройте Telegram, найдите бота, отправьте любой текст (например, "hello"), затем повторите попытку.

### Ошибка "Invalid token"

Токен бота неверный или истёк. Перейдите к @BotFather, отправьте `/mybots`, выберите бота и проверьте токен. При необходимости сгенерируйте новый.

### "Network error" или "Timeout"

Временная проблема с подключением. Подождите и повторите. Если проблема сохраняется, проверьте что сервер Moira может обращаться к `api.telegram.org`.

### Бот не отвечает

Боты, созданные через @BotFather, по умолчанию не отвечают на сообщения. Moira отправляет через них,
когда workflow выполняет `user-notification` при включённом Telegram, когда запуск начинает ждать
вас (или подходит срок напоминания), запускает устаревшую `telegram-notification` или выполняет
доверенную доставку PIN для `lock`.

### Уведомление не получено

1. Убедитесь что вы отправили сообщение боту (требование Telegram API)
2. Проверьте правильность chat ID (используйте @userinfobot для подтверждения)
3. Проверьте, что карточка Telegram включена и показывает **Готов** в **Настройки → Уведомления**
4. Проверьте что токен бота не был отозван
