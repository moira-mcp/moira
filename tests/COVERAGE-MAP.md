# Coverage map

Use this map to find the existing owner for a behavior and select the smallest useful suite.
Directories contain the maintained family; named files locate distinctive contracts. This is a
responsibility map, not an inventory of every assertion or a claim that all listed tests were run.
The [testing guide](TESTING-GUIDE.md) owns commands, level selection and cleanup. Actual discovery
belongs to the [runner configs](docs/test-infrastructure.md#discovery-and-preparation).

## codespace-connections

Workspace suites distinguish current observations from retained history and original operations.
An unavailable provider is not healthy absence; one provider's unresolved observation must not
block independent discovery of another. Original uncertainty and custody survive restart and
authority changes; collecting them does not repeat the effect or fabricate lifecycle authority.

[Controller availability](integration/local/controller-native-failure.test.ts) exercises real
archive publication and original collection during controlled native failure.
[Native admission](integration/local/native-admission.test.ts) covers retained authentication
refusal and runner exclusion; [runtime settlement](integration/local/runtime-settlement.test.ts)
covers exact-profile shutdown and preservation on refusal. These fixtures do not establish
physical VM or provider acceptance.

## Maintaining this map

When adding, moving or removing tests, update the relevant responsibility and suite location. Keep
one primary description and cross-link a shared suite rather than repeating its assertions under
multiple domains. Read actual cases before describing a boundary. Do not infer semantic overlap
from names, counts or shared keywords, and do not turn unavailable native/provider acceptance into
a fixture pass.
