# Workspace Connections

This reference describes the authenticated provider-connection boundary used by
Moira workspace services. GitHub Codespaces is the supported connection
provider, and the integration may be disabled by server configuration. Account
authorization belongs to the website; MCP and workflow agents do not receive an
authorization operation or provider credential.

## Component boundary

- `packages/shared/src/workspaces/connection-service.ts` owns the connection
  lifecycle, tenant checks, refresh serialization and safe status projection.
- `packages/shared/src/workspaces/connection-repository.ts` owns durable browser
  state, active credentials, pending revocations, installation grants and
  repository grants.
- `packages/shared/src/workspaces/credential-vault.ts` owns the versioned
  AES-256-GCM envelope. Authenticated context binds a credential to the Moira
  user, provider and opaque connection or revocation record.
- `packages/web-backend/src/services/github-workspace-client.ts` translates the
  GitHub App HTTP contract. Provider HTTP and browser callback behavior do not
  enter the shared database or vault modules.
- `packages/web-backend/src/routes/workspace-connections.ts` is the authenticated
  website boundary.
- `packages/web-frontend/src/pages/settings/GitHubWorkspaceSettings.tsx` renders
  the sanitized connection state in Settings.

The connection service exposes an internal tenant-resolved access-token method
to trusted server code. A caller supplies only the authenticated Moira user ID.
Connection IDs, OAuth state, refresh tokens, vault envelopes and revocation
capabilities are not caller inputs. No workspace MCP operation consumes this
method yet.

## Runtime configuration

Workspace GitHub configuration is distinct from `GITHUB_CLIENT_ID` and
`GITHUB_CLIENT_SECRET`, which belong to Better Auth social login.

| Variable                                 | Contract                                                          |
| ---------------------------------------- | ----------------------------------------------------------------- |
| `WORKSPACE_GITHUB_APP_CLIENT_ID`         | GitHub App client ID                                              |
| `WORKSPACE_GITHUB_APP_CLIENT_SECRET`     | Generated GitHub App client secret; server-only                   |
| `WORKSPACE_GITHUB_APP_CALLBACK_URL`      | Exact same-origin `/api/integrations/github/callback` URL         |
| `WORKSPACE_GITHUB_APP_INSTALL_URL`       | Exact `https://github.com/apps/<slug>/installations/new` URL      |
| `WORKSPACE_CREDENTIAL_VAULT_KEY`         | Dedicated random 32-byte key encoded as 64 hexadecimal characters |
| `WORKSPACE_CREDENTIAL_VAULT_KEY_VERSION` | Envelope key identifier; defaults to `v1`                         |

If all workspace values are absent, the feature is disabled. A partial, weak,
cross-origin or malformed configuration produces a safe configuration-error
status without aborting unrelated authentication. The callback uses HTTPS for a
public host and contains no query or fragment. Real values arrive through the
runtime environment and are not baked into the image.

Use the client secret generated by GitHub. Placeholder, repeated-character and
other low-diversity values are rejected before the provider becomes available.

The vault key must remain available under the configured version while its
records exist. A version or key mismatch makes the credential unreadable and
disables reconnect. The user must first revoke the Moira GitHub App grant in
GitHub Settings, then explicitly confirm that external revocation in Moira. Only
that confirmation permits deletion of unreadable local ciphertext. If the
operator restores the matching key and version first, Moira removes the stale
unreadable projection and permits ordinary Reconnect or Disconnect. Both paths
revoke the readable predecessor exactly; external confirmation cannot delete a
credential that is readable again.

## Website API

All routes are mounted under `/api/integrations` after the ordinary `requireAuth`
middleware.

| Method   | Path                          | Behavior                                                           |
| -------- | ----------------------------- | ------------------------------------------------------------------ |
| `GET`    | `/github`                     | Returns the current user's sanitized connection view               |
| `GET`    | `/github/start`               | Stores one-time browser state and redirects to GitHub              |
| `GET`    | `/github/callback`            | Consumes state, verifies GitHub identity/grants and redirects      |
| `DELETE` | `/github`                     | Disables local authority, revokes the GitHub grant and disconnects |
| `DELETE` | `/github/external-revocation` | Clears an eligible blocked state after external grant revocation   |

The external-revocation request body must be `{ "confirmed": true }`. The user
must revoke the GitHub App grant in GitHub before sending this confirmation;
Moira cannot prove that remote action when an envelope or refresh successor is
unavailable.

Start requires the current web-session token. Stored state is a SHA-256 digest
bound to the Moira user, session and provider, expires after ten minutes and is
consumed once. A newer start invalidates the user's earlier unconsumed state.
Unknown, expired, replayed, wrong-session and wrong-user values produce the same
safe authorization failure.

Callback redirects contain only a bounded `github` outcome on the configured
same-origin Settings URL. The backend request logger replaces the whole callback
query with `[REDACTED]`; both nginx modes omit that request from access logs.

## Credential lifecycle

The service accepts an expiring GitHub App user token only when it contains a
`ghu_` access token and rotating `ghr_` refresh token with valid expiries. A
classic `gho_` OAuth token is rejected. GitHub numeric identifiers are stored as
validated decimal strings so they are not truncated by JavaScript numbers.

Refresh claims a durable expiring lease and commits the new encrypted token pair
with a generation compare-and-swap. Concurrent processes wait for the committed
successor. Provider ambiguity, an expired refresh credential, unreadable
ciphertext or an abandoned lease prevents use of the predecessor token.
Unreadable ciphertext produces `CREDENTIAL_UNREADABLE` and cannot enter the
ordinary reconnect path.

Before submitting a refresh, the connection stores a durable recovery marker.
If GitHub may have issued a successor that Moira can neither retain nor revoke,
the connection returns `AUTH_GRANT_REVOCATION_REQUIRED` and disables Reconnect
and ordinary Disconnect. The user revokes the entire GitHub App grant in GitHub
and confirms that external action in Settings. A durably retained pending
successor instead follows exact token revocation and does not require this
full-grant recovery.

Before credential replacement, the previous pair is copied into an encrypted
pending-revocation record and revoked exactly. A credential issued during a
callback that later fails validation is handled the same way. The pending record
is deleted only after GitHub accepts revocation; a later website attempt or
Disconnect retries it. Disconnect moves the active connection to
`revocation_pending` before provider I/O and removes ciphertext and grants only
after a terminal provider outcome.

## Browser states

The Settings integration renders `disabled`, `configuration_error`,
`connection_required`, `connecting`, `installation_required`, `connected`,
`refresh_failed`, `revocation_pending` and `disconnected`. The response can
include the verified GitHub numeric account ID/login and approved repository
summaries. It never includes a provider token, client secret, vault key,
connection ID or revocation ID.

Connection and reauthorization actions are browser navigation. The current
connection component exposes no agent-facing workspace operation, authorization
start, callback, device flow or polling method.

When active/pending ciphertext cannot be decrypted, or a submitted refresh may
have produced a successor that could not be retained or revoked, Settings
disables Reconnect and shows the explicit external-revocation recovery. The
destructive confirmation is valid only after the user has removed the Moira
GitHub App grant in GitHub; it clears tenant-owned local ciphertext and grants
and records an `external_revocation_confirmed` audit outcome. Restoring readable
vault material removes unreadable-recovery eligibility and exposes ordinary
Disconnect.

## Persistence

Migration `0025_workspace_connections.sql` owns these tables:

- `workspaceConnection` — tenant/provider metadata and refresh lease;
- `workspaceCredentialVault` — the active versioned ciphertext envelope;
- `workspaceCredentialRevocation` — encrypted exact pending revocations;
- `workspaceAuthorizationState` — digested browser state;
- `workspaceConnectionInstallation` and `workspaceConnectionRepository` —
  non-secret GitHub grants.

The schema has no access-token, refresh-token or client-secret column. The normal
startup migration and self-host backup/restore guard own upgrades and rollback.

## Audit boundary

Connect start/completion, refresh failure and disconnect use workspace audit
actions. Metadata contains the actor, provider, opaque resource and outcome.
Source, repository contents, OAuth code/state, session token and provider
credentials are excluded.
